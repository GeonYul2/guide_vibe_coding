# Agent Intake Form: customer-email-reply-agent

이 문서는 짧은 사용자 요청을 실행 가능한 자동화 에이전트 요구사항으로 정규화한 접수 양식입니다. 일부 세부 정책은 실제 도입 전에 deep interview로 확인해야 하지만, validator 검증을 위해 가상 시뮬레이션 기준의 명시적 가정을 기록합니다.

## Agent Idea

고객 문의 메일을 읽고 회사 정책 문서를 참고해 답변 초안을 작성하는 고객 지원 보조 에이전트입니다. 애매하거나 위험한 요청은 답변을 보내지 않고 사람 상담원에게 넘깁니다.

## Primary User

초기 사용자는 고객지원팀 상담원과 지원 운영 매니저입니다. 상담원은 초안을 검토하고, 매니저는 정책 준수와 품질 지표를 관리합니다.

## Workflow Pain

반복 문의 답변에 시간이 많이 걸리고 상담원마다 정책 해석과 문체가 달라 품질 편차가 생깁니다. 정책 문서 검색, 답변 초안 작성, 애매한 케이스 분류를 표준화해야 합니다.

## Input

입력은 고객 이메일 제목과 본문, 고객 등급 같은 제한된 CRM 메타데이터, 회사 정책 문서 검색 결과, 상담원이 추가한 처리 지시입니다. 첨부파일은 첫 버전에서 텍스트 추출이 완료된 경우만 사용합니다.

## Output

출력은 사람이 검토할 답변 초안, 참조한 정책 문서 링크와 근거 요약, 신뢰도 점수, 고객에게 바로 보내면 안 되는 이유, 사람 검토 필요 여부를 포함한 구조화 JSON과 Markdown 요약입니다.

## Allowed Actions

사람 승인 없이 이메일을 읽고 분류하며, 정책 문서를 검색하고, 답변 초안을 작성하고, 내부 검토 큐에 저장할 수 있습니다. 외부 고객에게 직접 발송하지는 않습니다.

## Human Approval Required

고객에게 이메일을 실제 발송하는 작업, 환불이나 보상 약속, 계정 권한 변경, 법무·보안·개인정보 관련 답변, 정책 문서에 근거가 부족한 답변은 상담원 또는 매니저 승인이 필요합니다.

## Forbidden / Non-Goals

첫 버전은 고객에게 자동 발송하지 않고, 정책을 새로 만들거나 수정하지 않으며, 환불·계약·법률 판단을 확정하지 않습니다. 민감정보를 로그에 원문 저장하거나 승인 없이 외부 시스템을 변경하지 않습니다.

## Success Examples

1. 배송 지연 문의를 읽고 배송 정책 문서를 근거로 정중한 답변 초안과 검토 체크리스트를 생성합니다.
2. 환불 예외 요청을 감지하고 보상 약속 없이 사람 검토 큐로 넘깁니다.
3. 정책 문서에 답이 없는 문의를 낮은 신뢰도로 표시하고 추가 정보 요청 문안을 제안합니다.

## Failure / Edge Cases

고객이 법적 책임이나 보상을 요구하는 경우, 정책 문서가 서로 충돌하는 경우, 고객 이메일에 카드번호나 주민등록번호 같은 민감정보가 포함된 경우, 정책 검색 API가 실패하는 경우를 안전하게 처리해야 합니다.

## Tools / Data Access

읽기 전용 이메일 수신함, 읽기 전용 정책 문서 검색, 제한된 CRM 메타데이터, 내부 검토 큐 쓰기 권한만 사용합니다. SMTP 발송, 결제 시스템, 계정 권한 시스템, 원문 민감정보 저장소 접근은 첫 버전에서 제외합니다.

## Evidence of Success

Fixture 이메일 20건 기준으로 JSON schema validation 100%, 정책 근거 포함률 95% 이상, 고위험 문의 handoff 100%, 자동 외부 발송 0건, 상담원 품질 평가 평균 4점 이상을 달성하면 성공으로 봅니다.
